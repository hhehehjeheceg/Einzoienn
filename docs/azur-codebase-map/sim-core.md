# sim-core

## Architecture
Load order of these files (index.html:60-82): runtime.js → vendor/three.min.js (r158 UMD) → world-split.js → game-zeropoint.js → sim.js → build-rules.js → meta, audio, models, ... view.js, game.js (class Game = AZGame), map-ui, garage → social-client.js → client.js. client.js does 'class Horizons extends AZGame', calls AZSocial.install(Horizons) at line 1600, then 'new Horizons()' at line 1603. After that come horizons-v120..v180, graphics-v200, polish, construction.js, map-poi-v67, island-v68, weapons, skins, anim, emotes, lobby, hud, inventory, construction-v67, ui-v81, then about 30 event-*.js files, zeropoint-v82, lobby-v83 and weapons-v84. Because the Horizons instance exists before the later files load, later files patch prototypes (Horizons.prototype, AZView.View.prototype, AZSim.World.prototype); the instance picks the patches up through the prototype chain.

Runtime model. sim.js is the single source of gameplay truth. game.js creates new S.World({mode, seed, player}) (game.js:138 training at boot; client.js:1493 in startMatch). Each frame it calls world.command(myId, input) (game.js:742) and steps world.step(1/60) up to 6 times (game.js:1103-1110). View and audio read world state directly and consume world.events by increasing id (view.js:1092). Match flow: phase 'waiting' (10 s, on the offshore island) → 'transport' (bus; humans must press jump; bots jump at scheduled times) → 'active' (storm, combat) → 'ended'. In LAN mode (inactive), client.world is replaced by server JSON snapshots with no methods.

Patch layering on World.prototype: build-rules.js (buildPlacement wrap, canBuild replace, _build/_setEdit/step wraps, plus new hasBuildSupport/collapseUnsupported) → map-poi-v67.js:43 (_createMap wrap: POI props and chests) → event-buscrash.js:506-518 (step and _deployFromBus wraps, installed on demand) → event-end81-play.js:212 (temporary supportAt/_blocked swap) → event-player.js:355/382 (temporary per-instance w._damage / w._bot during the event). On THREE: world-split.js turns Material.prototype.onBeforeCompile into an accessor and replaces customProgramCacheKey; game-zeropoint.js replaces the THREE.Scene constructor with a capturing wrapper. On Horizons.prototype: social-client wraps boot, menuRoster, lobbyHTML, connect and action. horizons-v150.js:46 later REPLACES lobbyHTML outright, dropping all earlier lobbyHTML layers, including social's relabel.

## How to modify safely
1. Gameplay rules: edit sim.js directly, or wrap World.prototype methods in a new file loaded AFTER build-rules.js. Use the existing guarded pattern: `const W=AZSim.World.prototype; if(!W._myV){W._myV=1; const prev=W._storm; W._storm=function(dt){...; return prev.apply(this,arguments);};}`. Never replace sim.js canBuild: build-rules.js:63 replaces it entirely, so build-validation changes belong in build-rules.js (or a wrapper loaded after it).
2. Closure pitfall: sim.js internals call heightAt, coastDistance, makeInv, buildPlacement, weapons, rarities, regions and MAP through closure variables. Re-assigning AZSim.heightAt = fn or AZSim.weapons = {...} after load has NO effect inside the sim. Shared objects can be mutated in place (e.g. AZSim.weapons.rifle.damage=..., AZSim.MAP.transport.altitude=..., AZSim.rarities[0].color=...). MAP.transport is read every tick, so route, speed and altitude changes apply live. FLIGHT and EMOTE_STYLES are Object.freeze'd, so change them in sim.js source. Adding regions after load spawns houses (in _createMap) but no street lattice or roads (both built at load, sim.js:129-135), and it changes _safeSpawnGoal slots. Edit the regions array in sim.js instead, keeping each style a key of districtGrid/districtDensity.
3. Hard-coded values to change together. Warm-up 10 s: sim.js:415. Bus route: MAP.transport plus aircraft.yaw at sim.js:241, which is never recomputed. Humans are not auto-ejected (sim.js:408 and 422); add a forced release, e.g. when _transportTime > duration, call _deployFromBus with an override or relax the `forced&&!p.bot` guard. Hotbar size 5: sim.js:386 (slot<5), 585, 1002 (inventory.length<5), 1132, plus client HUD files; a 6th 'pickaxe slot' should stay implicit (empty slot = harvest, sim.js:878) or every check must change. Bot damage scaling: sim.js:924-930. Storm schedule: sim.js:240 and 1107-1116. Chest contents and rarity odds: sim.js:272-276. Consumables: 2.7 s/+45 and 2.2 s/+35 at sim.js:953-954. Shared ammo types would need new inventory fields (e.g. p.ammo {light, medium, heavy, shells, rockets}), changes in makeInv, _startReload/_finishReload, _dropLoot, _dropAll and _interact, and new loot kind 'ammo'. The snapshot carries non-underscore fields automatically.
4. Network visibility: snapshot() strips every key starting with '_' (sim.js:1148). Use plain names for state the HUD needs in LAN mode (e.g. expose stormState) and '_' names for private state.
5. Events: world.events keeps only the last 100 (sim.js:267) and the view reads by id once per frame. Each shotgun pellet emits a 'shot' event and up to 6 sim steps run per frame, so heavy fights can overflow. Keep new event types sparse, or raise the cap carefully. Add payloads (e.g. amount and material to 'harvest' at sim.js:1010) rather than new event types when you need '+N' popups.
6. Determinism: inside the sim, use this.rng (seeded), never Math.random, so seeded tests and LAN replays stay consistent. Keep dt clamped (≤ .05).
7. Mode guards are scattered ('training', 'creative', 'event' at sim.js:416, 426, 481, 930, 1118). Any new BR rule must respect them or the event, creative and training modes break.
8. The in-match Zero Point is three pieces: sim.js:244-246/427/432-456 (logic), game-zeropoint.js (dead visual) and zeropoint-v82.js (actual visual). To remove it for Chapter-1 fidelity, delete the sim block and both script tags together. Deleting game-zeropoint.js also restores the real THREE.Scene constructor. Do NOT delete world-split.js unless the event files are removed too: event-zerorage.js:18 reads AZSplit.uniforms without a guard.
9. world-split.js applies to every material created after it loads. Rules for new materials: (a) set onBeforeCompile by normal assignment, which is captured and chained, never by Object.defineProperty; (b) if you override customProgramCacheKey, return a unique string per shader variant; (c) for avatar, weapon or outline materials that must not deform during THE END, set material.userData.azRigid = true. The newer skins-v81/v89 outline and rim keys are currently missing from the RIGID list.
10. social-client.js wraps Horizons methods at client.js:1600, before every horizons-v*/lobby/ui file. Lobby redesigns that REPLACE lobbyHTML or action (horizons-v150 already does for lobbyHTML) silently drop the social behavior. Wrap instead (const prev=P.action; P.action=async function(a,i,e){...; return prev.call(this,a,i,e);}). It is safe to leave untouched while AZ_RUNTIME.network is false.
11. A cleaner way to make large changes than patching inside the long minified lines: add a new file (e.g. br-ch1.js) right after build-rules.js in index.html that wraps or mutates World.prototype and AZSim data, and bump the ?v= cache-buster on every script and link tag. Then verify in the browser with an in-match screenshot, because there is no automated test harness in the repo.

The match stays in 'transport', with no storm, until every living human has jumped, while the bus flies on past the island; Fortnite auto-drops players at the end of the route. Freefall runs at 26 m/s (30 when diving) with a pitch-driven dive. Jump while falling opens the glider. The glider auto-opens 135 m above the ground. Glide speed is 36-42 m/s with 4.6-5.4 m/s sink. The glider can be closed again while above 135 m. Landing emits 'land' or 'splash'. Trails, the balloon-bus model and the camera live elsewhere (bus-v82.js, view).

Towns are regular grids, unlike Fortnite's hand-authored POIs. The comment '16 settlements' at sim.js:351 is stale.

  There are 10 weapons: pistol, revolver, AR 'rifle', burst rifle, SMG, pump 'shotgun', tactical shotgun, sniper, DMR and rocket 'launcher'. The 5 rarity colors are #aab8c8 / #58c983 / #3f9cff / #a56bff / #ffad31, close to gray/green/blue/purple/gold, and rarity changes only a damage multiplier (1 to 1.6). Reload times are per weapon. Damage against bots is scaled ×0.30 (sim.js:925), so a bot effectively has about 333 HP against human weapons, which strongly changes how fights feel.
