# models-chars

## Architecture
Script order (index.html): runtime, three.min (r15x UMD), world-split, game-zeropoint, sim (AZSim), build-rules, meta (AZMeta), audio, models.js (L68: creates AZArt), graphics-v48-hero (L69: turns AZArt.avatar and AZArt.weapon into accessor properties), vehicles-v74 (replaces vehicleModel except boat), bus-v82 (replaces aircraft, falls back to models.js), graphics-v48-city, environment, icons, view.js (AZView.View, base animateAvatar at L405), render-upgrades (solveArm, weapon IK, emote poses, wraps animateAvatar), panels, game, map-ui, garage, social-client, client, horizons-v120..v170, graphics-v200-art (L89: new avatar/weapon, buildModel passthrough, goldMaterial), graphics-v200-world (L90: objectModel wrapper, lobby scene), graphics-v200-engine, horizons-v180, polish-v47, construction, map-v65, map-poi-v67, island-v68, characters-v67 (L98), weapons-v67/v71, weapons-sfx-v69, music-v69, loot-v67, render-toon (L104: wraps avatar for outlines), skins-v81 (L105), skins-v89 (L106), anim-v67 (L107), emotes-v67 (L108), lobby-v66, lobby-v89, hud-v67, inventory-v67, construction-v67, ui-v81, then the event-*.js files, zeropoint-v82, lobby-v83, weapons-v84.

Effective avatar call chain when anything calls AZArt.avatar(eq, detail): graphics-v48-hero dispatcher, level 0 runs skins-v89, whose base call runs skins-v81 at level 1, then render-toon at level 2, then graphics-v200-art avatar at level 3. That last one does NOT call models.js avatar. On return at level 0, the v48 'hero' material is swapped onto shared vertex-colour meshes. skins-v89 then dresses LOOKS ids and skins-v81 dresses SKINS ids, each hiding the underlying meshes. The weapon chain is similar: weapons-v71, then weapons-v67 for unknown keys, then graphics-v200-art. The models.js weapon is never reached.

Per-frame avatar animation chain: view.js base, then render-upgrades, horizons-v140/v160/v170/v180, polish-v47, characters-v67 (blink, rarity gun, gold), then anim-v67, which re-poses legs/torso/head and also the arms when not holding a gun or blueprint. Runtime event wrappers (event-player, event-animation, event-end81-play) sit on top. characters-v67 also wraps View.update for the gold clock and gold loot. emotes-v67 runs on its own 100 ms timer and is not attached to the render loop.

Live code in models.js: Model helper, C, material, rng, cosmetic, house shell, objectModel branches for chest/container/silo/lamp/fence/dock/crate, buildModel (all player builds and ghost previews), vehicleModel for boat, and aircraft as a fallback only. Dead code: avatar, weapon, launchTerrace, the tree and rock branches (replaced in graphics-v200-world) and the car branches (replaced in vehicles-v74).

The game is a French-language original 'AZUR Horizons' battle royale. The five assigned character files hold the whole character pipeline (models, skins, animation, emotes) plus base world and build geometry. They contain no HUD, storm, loot logic, AI or networking.

## How to modify safely
1. Respect the accessor chain on AZArt.avatar and AZArt.weapon (graphics-v48-hero.js:47-63). Never Object.defineProperty these keys again. To wrap one, write `var base = A.avatar; A.avatar = function(eq, d){ var g = base.apply(this, arguments); /* modify g */ return g; }`. Call base exactly once, synchronously, inside the wrapper; the dispatcher counts call levels, so skipping or repeating base breaks the chain. Assigning a function that does not call base silently removes every lower layer. After wrapping, re-export with `if (root.AZView) root.AZView.avatar = A.avatar`. A new skin file must load after skins-v89 (before anim-v67 is fine), or it must edit skins-v89 directly.

2. To change the default look (for example a recruit-style soldier with an olive shirt, tactical vest, cargo pants and no headset), the cleanest place is skins-v89.js:
   - Add a LOOKS entry (sleeves 'full', headset false, olive/khaki colours).
   - To get a real vest, add a 'vest' value for `top` and a third branch in paintTorso (L441-525), buildTorso (L710-757) and buildPack (L856-892).
   - Set DEFAULT to the new id. Rename the migration flag (`kai089` at L63) to a new key, otherwise existing saves will not re-equip.
   - Catalog entries are pushed at script load, before AZMeta.normalize runs, which keeps the base validation in meta.js:534-539 happy.

3. Rig contract shared by every skin and animator:
   - limbs = [hipL, shoulderL, hipR, shoulderR], knees[2], elbows[2], torso, head. u.pelvis is replaced by skins-v89.
   - Sign conventions are in anim-v67.js:10-13.
   - Parent new meshes to these groups. Tag them (userData.v89 or your own marker) so the hide passes (skins-v89 hideOldDeep L901, skins-v81 hideBase L79) do not hide them.
   - Set userData.shared=true on meshes with cached materials. View.disposeTree (view.js:147) disposes geometry always, and materials unless they are shared.
   - Keep u.gun, u.tool (with userData.v67=true, or anim-v67 skips the swing), u.glider.userData.handles, u.blueprint and u.lids.

4. Animation changes belong in anim-v67.js: locomotion (L33-168), pickaxe (L170-265), emotePose (L268-346), apply (L349-362).
   - It runs after render-upgrades and overrides it, except for the arms while a gun, blueprint or rod is visible.
   - It sets model.rotation.x/z every frame outside the menu; anything else that tilts the root must run after it.
   - Errors are swallowed (L405); add console.error there while developing.
   - To add an emote, update four places together: sim.js EMOTE_STYLES (L26), render-upgrades EMOTE_STYLES (L62), anim-v67 BPM plus a branch in emotePose, and emotes-v67 SONGS. Otherwise sim validation (sim.js:379) rejects the style.

5. World and build art: the chest look is in models.js objectModel (L1172-1199); keep userData.lid and userData.light, which view.js:763-764 animates. Trees, rocks and house trim are in graphics-v200-world.js:349-394, not models.js. House collision is a single authoritative box in the sim, so adding walkable interiors or stairs needs sim/collision changes too, not just geometry. Build pieces must stay inside the 3x3 cell footprint and honour editMask (comment at L1244-1246); the ghost material is at L1371-1377 and later scripts animate its opacity. The battle bus is in bus-v82.js; keep the userData contract (balloon non-null, cameraTarget, cameraRadius, turbines, etc.) used by view.js:375-378 and 949-970.

6. Remove the outlines and rim light to match Fortnite Chapter 1's smooth PBR look: skins-v89 outline at L610-612 and L898, rim shader at L604-607; skins-v81 outline at L60-62 and L76; render-toon.js; graphics-v48-hero's hero rim material.

7. Weapons: edit weapons-v67, weapons-v71 or weapons-v84, not models.js weapon(), which is unreachable. Held-weapon rarity tinting is in characters-v67.js:58-68. Reference-style rarity (weapon keeps its colours, rarity shown in UI and loot glow) means passing a neutral colour there instead of rarities[].color.

8. Bump the ?v=91 cache-busting query in index.html for every edited file, and keep the script order. characters-v67 needs graphics-v200-art (goldMaterial); the skins need AZMeta.catalog and normalize; anim-v67 needs render-upgrades solveArm; emotes-v67 needs AZUR.audio.musicBus and AZUR.player().

9. If the goal is a full Fortnite-like rebuild, prefer a new layered file (for example skins-v92.js or anim-v92.js) loaded after the files it wraps, following the same capture-then-replace pattern. That keeps the version history intact. Editing old layers in place also works, but check every later wrapper that captured the old function.
