Script order (index.html:60-153): runtime, three r158 (vendor/three.min.js, global THREE), world-split, game-zeropoint, sim (AZSim), build-rules, meta, audio, models (#68, defines AZArt incl. shared material, avatar, weapon, aircraft, launchTerrace), graphics-v48-hero (#69), vehicles-v74, bus-v82 (replaces A.aircraft), graphics-v48-city (#72), environment (#73), icons, view (#75), render-upgrades (#76), panels, game (Game class creates new AZView.View in async boot after loadProfile + 1 rAF, game.js:135), map-ui, garage, social-client, client (#82, AZURHorizons; new Horizons() at client.js:1603; boot binds view.update on the instance at client.js:1255-1257), horizons-v120..v170, graphics-v200-art (#89, replaces A.avatar/weapon/buildModel, defines A.fx), graphics-v200-world (#90), graphics-v200-engine (#91), horizons-v180, polish-v47, construction, map-v65, map-poi-v67, island-v68, characters-v67, weapons-v67, weapons-v71, weapons-sfx-v69, music-v69, loot-v67, render-toon (#104), skins-v81, skins-v89, anim-v67, emotes-v67, lobby-v66, lobby-v89, hud-v67, inventory-v67, construction-v67, ui-v81, then about 32 event-*.js files, zeropoint-v82, lobby-v83, weapons-v84 (last).

- Environment.prototype.update: island-v68 -> map-poi-v67 -> map-v65 -> horizons-v180 (173) -> horizons-v180 (89) -> graphics-v200-world (FULL REPLACEMENT). environment.js update and the horizons-v160 wrap are dead. installWorldV2 hides or replaces the environment.js sky, clouds, stars, birds and water and recolours the terrain; island-v68 recolours it again.
- AZArt.avatar (via the graphics-v48-hero accessor): hero wrapper -> skins-v89 -> skins-v81 -> render-toon -> graphics-v200-art (base). AZArt.weapon: hero wrapper -> weapons-v71 -> weapons-v67 -> graphics-v200-art -> models.
- Global three.js patches: Object3D.prototype.add and Mesh.prototype.onBeforeRender (graphics-v48-city). Instance-level renderer.render patch (render-toon, ultra only). AZURHorizons.prototype.loop (engine).

Rendering model: the simulation is authoritative (AZSim). The view streams meshes by distance with per-frame creation budgets, uses instanced impostors for far houses and players, and draws the menu scene separately when opts.menu is set. Visual style: bright stylised palette, ACES tonemapping, CSS saturate(1.3) grade, character ink outlines. Text is French. Coordinates: Y up, avatar forward is -Z at yaw 0 (camera back vector is (sin yaw, -sin pitch, cos yaw)), weapons are authored along -Z.

## How to modify safely
1. Prefer a new layer file appended at the END of index.html (after weapons-v84.js), using the established wrap pattern: const prev = V.method; V.method = function(...a){ const r = prev.apply(this, a); ...; return r; }. Keep the ?v=91 cache-buster consistent (bump it everywhere when files change). Editing the base files only helps for code that is still live. Do NOT tune view.js configure, adaptPerformance, makeMenu or drawMenu, environment.js update/makeSky/makeWater/terrainColor, render-upgrades drawMenu, or the graphics-v200-engine makeMenu wrapper: they are dead or overwritten (see architecture_notes). Quality presets live in graphics-v200-engine.js:10-16. The lobby 3D lives in graphics-v200-world (drawMenu), lobby-v66 (makeLobby), lobby-v89 and lobby-v83.
2. The render happens inside the base view.js update (line 1141) and inside the v200 drawMenu (graphics-v200-world.js:494). Post-wrappers that change materials or transforms after calling the base take effect one frame late. For same-frame changes, set state BEFORE calling prev, or edit view.js update directly (for example the storm at 1046-1052, the camera at 976-1044, the ghost at 1053-1086, loot at 810-851). Some values are re-set every frame inside view.js update (hemi and sun intensity, sun colour, fog colour and density, exposure lerp, skyFill intensity), so changing them in configure or once at startup has no lasting effect. Change them in view.js update (737-750) or right before calling the base update.
3. Storm visuals (stormWall and stormRing) are touched by no other file. To get a Fortnite look, edit view.js makeEffects (176-195): a denser purple swirl shader with higher alpha, and a ring that follows terrain or uses a decal. Add an inside-storm screen tint in a HUD/DOM layer, keyed on Math.hypot(p.x-w.storm.x, p.z-w.storm.z) > w.storm.radius.
4. Character poses: render-upgrades resetRig() wipes the base view.js pose every frame. Add pose changes in a wrapper loaded after anim-v67, or inside render-upgrades. Keep using the stateful counters u.walk, u.anim, u.recoil, u.harvest and u.glideScale (owned by the view.js base; do not tick them twice). Rig indices: limbs[0] L-leg, [1] L-arm, [2] R-leg, [3] R-arm. solveArm(u, 1, target) is the right/primary hand; targets are in avatar-root space.
5. AZArt.avatar and AZArt.weapon are accessor properties (graphics-v48-hero). Always wrap as const base = A.avatar; A.avatar = function(eq, detail){ const g = base.apply(this, arguments); ...; return g; } and call base exactly ONCE per invocation. The accessor walks its chain by call depth, so calling A.avatar twice inside a layer, or creating a nested avatar from inside a layer, can call the wrong chain entry. Reading A.avatar always returns the wrapper, and assigning pushes onto the chain (you cannot remove a layer by assignment). Meshes using the shared AZArt.material are switched to heroMaterial at the outermost level. render-toon outlines run at an inner level, so parts that skins add later are not outlined. To match Fortnite (no ink outlines), remove the outline wrap in render-toon.js:36-48, or make the condition false (outlinesOn), rather than stripping hulls afterwards.
6. Materials and disposal: View.disposeTree skips materials on meshes flagged userData.shared and AZArt.material. Flag any shared material you introduce, or it will be disposed when an actor, build or loot mesh is evicted.
7. graphics-v48-city patches THREE.Object3D.prototype.add globally. Every add() traverses the subtree, and vertexColors materials without a colour attribute get white added. Avoid adding huge groups every frame, and give geometries real colour attributes when using vertexColors.
8. render-toon: the CSS canvas filter is not captured by canvas.toDataURL or readPixels screenshots, so verify visuals with real screenshots. On ultra, renderer.render is monkey-patched per instance; any additional on-screen render with a PerspectiveCamera goes through the post pass. Render overlays (for example a sniper scope scene) to a render target, use an OrthographicCamera, or use DOM/CSS for the scope.
9. Boot timing: View is created inside async boot (game.js:135), and client.js binds view.update on the instance (client.js:1255-1257). Prototype methods are looked up at call time, but the constructor work (makeMenu, makeEffects, Environment), the first configure() call and the instance-bound update capture whatever existed at that moment. A late layer should, like graphics-v200-world.js:515-517 and polish-v47.js:392-400, handle an existing root.AZUR.view: re-run makeMenu or configure(profile.settings), and wrap the instance update if Object.prototype.hasOwnProperty.call(view, 'update').
10. Environment changes: new map art belongs in a wrapper of Environment.prototype.update with a lazy ensureX() (the pattern of map-v65, map-poi-v67 and island-v68), added to env.root. Terrain heights come from S.heightAt (sim.js) and are baked into the mesh at construction, so changing the topology (rivers, a central lake, hills) means changing sim.js heightAt/biomeAt to keep collision consistent; roads re-sample via surfaceHeight. Rock formations and scenery are not in S.objects, so they cannot be harvested; harvestable trees and rocks must be sim objects.
11. Respect the existing caps and keep hot loops allocation-free: particles 280, shotEffects 56, texts 18, farActors 101, houseLOD 900, near actors 8/12/18/24, object creation 2 per frame within 2.2 ms. Use the scratch vectors (_scratchV1-3, _camT etc.).
12. Rarity colours come from sim.js:35-41, used by view.js loot rings and weapon tint. Change them at the source to propagate. Fortnite uses grey #b0b0b0-ish, green #60aa3a, blue #3c8edb, purple #a34ee0 and gold #e9a43c.

- [5] Island map: POIs, rivers, central lake, hills, buildings with interiors, trees, rocks, roads — **partial** @ environment.js:94-128 (terrain), 186-241 (roads), 242-277 (grass), 278-352 (lamps, benches, region name signs, flags, coast rocks), 357-389 (rock formations), 394-476 (scenery POIs); view.js:204-212, 751-781 (detailed object streaming + house LOD); graphics-v48-city.js (LOD facade shader)

  Camera target is the player plus 1.82 m (1.3 crouched). Boom distance is 3.7 on foot, 2.2 ADS, 1.65 sniper ADS, 6.2 in air and 9.4 in a vehicle, times AZEvent.cameraZoom. There is a 0.5 m right-shoulder offset (times AZEvent.cameraShoulder), the boom is clamped above terrain, and a raycast against nearby house meshes (35 m) and builds (9 m) pulls the camera in. Fortnite's default FOV is about 80, with a wider right offset that puts the character left of centre. Movement and collision physics are in sim.js, not in these files. The animations exist (stride, sprint lean, launch dip, brake skid, crouch blend, jump anticipation and flight).
